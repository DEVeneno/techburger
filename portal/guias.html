O primeiro pull request (o seu card)

  1. Entre no GitHub e abra github.com/aprendendodev/techburger.
  2. Clique na pasta equipe, abra o _modelo.md e copie o texto. Volte para a pasta e clique em Add file › Create new file.
  3. O GitHub pede um fork: clique em Fork this repository.
  4. No nome do arquivo, digite seu-usuario.md (o seu usuário do GitHub). Cole o modelo e preencha. Só o primeiro nome.
  5. Clique em Commit changes..., escreva Adiciona card de @seu-usuario e clique em Propose changes.
  6. Confira em Comparing changes: 1 arquivo novo, só o seu. Clique em Create pull request.
  7. Preencha o modelo do PR. Na Issue, escreva Parte de #1. Clique em Create pull request.
  8. Aguarde a revisão. Se o professor pedir mudança, edite o arquivo no seu fork, na mesma branch (patch-1): o PR se atualiza sozinho.

Atualizar o seu fork antes de cada tarefa

Os colegas vão fazendo merge no repositório da empresa, e o seu fork fica para trás. Antes de começar uma tarefa nova:

  1. Abra o seu fork: github.com/seu-usuario/techburger.
  2. Clique em Sync fork › Update branch.

Entregar uma tarefa da sprint

  1. Na página Sprint, escolha uma tarefa Livre do seu squad e clique em Pegar esta tarefa.
  2. Na Issue, comente /eu-pego. O robô do time responde e a tarefa fica com você (1 tarefa por vez; para devolver, comente /largar).
  3. Leia a história, o critério de aceite e o arquivo da tarefa. Atualize o seu fork (guia acima).
  4. Faça a alteração no seu fork, só nos arquivos do seu squad. No commit, escolha Create a new branch com um nome que diz o que é: carrinho-pedido-minimo.
  5. Abra o pull request com Closes #número-da-issue e o diagrama de referência. O cartão vai para Em revisão.
  6. Peça ao Tech Lead do squad que revise. Ajuste o que ele ou o professor pedirem, na mesma branch.
  7. Depois do merge, a Issue fecha sozinha e o cartão vai para Pronto.

Entregar um diagrama do draw.io

  1. Desenhe em app.diagrams.net e salve como .drawio (nome sem espaço e sem acento: casos-de-uso.drawio).
  2. No seu fork, abra docs/diagramas/seu-squad/ e clique em Add file › Upload files.
  3. Arraste o arquivo, escreva a mensagem (Cria casos de uso do carrinho), escolha Create a new branch e clique em Propose changes.
  4. Abra o pull request com Closes #número-da-issue.

Editar código no navegador (github.dev)

  1. Abra o seu fork e aperte a tecla . (ponto): abre um editor de código igual ao VS Code, dentro do navegador.
  2. Edite os arquivos do seu squad. Na barra da esquerda, o ícone de Source Control mostra o que mudou.
  3. Escreva a mensagem do commit e clique em Commit & Push. Para uma branch nova, clique no nome da branch (canto inferior esquerdo) e crie a branch antes.
  4. Volte ao GitHub e abra o pull request.

O github.dev não roda o app. Para ver o resultado, baixe o fork (Code › Download ZIP) e abra src/index.html no navegador, ou aguarde o merge e veja em aprendendodev.com.br/app.

Em casa: Git e VS Code instalados (opcional)

  1. Instale o Git e o VS Code.
  2. No terminal: git clone https://github.com/seu-usuario/techburger.git
  3. Para cada tarefa: git switch -c nome-da-branch, edite, git add ., git commit -m "Verbo + o quê", git push -u origin nome-da-branch.
  4. Abra o pull request pelo site do GitHub.
