O primeiro pull request (o seu card)

Jeito rápido: a página Começar monta o card e abre o GitHub com o arquivo já preenchido. Jeito à mão:

  1. Entre no GitHub e abra github.com/aprendendodev/techburger.
  2. Clique na pasta equipe, abra o _modelo.md e copie o texto. Volte para a pasta e clique em Add file › Create new file.
  3. O GitHub pede um fork: clique em Fork this repository.
  4. No nome do arquivo, digite seu-usuario.md (o seu usuário do GitHub). Cole o modelo e preencha. Só o primeiro nome.
  5. Clique em Commit changes... e depois em Propose changes.
  6. Confira em Comparing changes: 1 arquivo novo, só o seu. Clique em Create pull request.
  7. Preencha o modelo do PR. Na Issue, escreva Parte de #1 (se esquecer, o robô coloca). Clique em Create pull request.
  8. O robô do time confere o card e comenta no PR. Se o professor pedir mudança, edite o arquivo no seu fork, na mesma branch (patch-1): o PR se atualiza sozinho.

Atualizar o seu fork antes de cada tarefa

Os colegas vão fazendo merge no repositório da empresa, e o seu fork fica para trás. Antes de começar uma tarefa nova:

  1. Abra o seu fork: github.com/seu-usuario/techburger.
  2. Clique em Sync fork › Update branch.

Entregar uma tarefa da sprint

A página Sprint › Minha tarefa mostra o seu próximo passo com os botões certos. O caminho completo:

  1. Na página Sprint, escolha uma tarefa Livre do seu squad e clique em Pegar esta tarefa. A Issue abre e o /eu-pego já fica copiado.
  2. Na Issue, cole (Ctrl+V) na caixa de comentário e clique em Comment. O robô responde e a tarefa fica com você (1 tarefa por vez; para devolver, comente /largar).
  3. Leia a história e o critério de aceite. Na resposta do robô (ou em Minha tarefa), clique em Editar: o arquivo da tarefa abre no GitHub. Se pedir, clique em Fork this repository.
  4. Escreva o que o critério pede. Clique em Commit changes..., escreva o que fez (Preenche a entrevista do cardápio) e clique em Propose changes.
  5. Clique em Create pull request, escreva Closes #número-da-issue no campo Issue e o diagrama de referência. O robô confere o PR e a tarefa vai para Em revisão.
  6. Peça ao Tech Lead do squad que revise. Ajuste o que ele ou o professor pedirem, no seu fork, na mesma branch.
  7. Depois do merge, a Issue fecha sozinha e a tarefa vai para Pronto.

O seu fork ficou velho (os colegas já fizeram merge de outras coisas)? Faça o Sync fork antes de editar.

Entregar um diagrama do draw.io

  1. Em Minha tarefa, clique em Abrir no draw.io: o ponto de partida do seu squad abre no navegador. (Também dá para usar o draw.io instalado no laboratório.)
  2. Desenhe. Para salvar: Arquivo › Salvar como › Dispositivo, com o nome exato do arquivo da tarefa (ex.: casos-de-uso.drawio, sem espaço e sem acento).
  3. Clique em Enviar (se o GitHub pedir, Fork this repository), arraste o arquivo, escreva a mensagem (Cria casos de uso do carrinho) e clique em Propose changes. O arquivo novo substitui o ponto de partida.
  4. Clique em Create pull request com Closes #número-da-issue (se esquecer, o robô coloca).

Editar código no navegador (github.dev)

  1. Abra o seu fork e aperte a tecla . (ponto): abre um editor de código igual ao VS Code, dentro do navegador.
  2. Edite os arquivos do seu squad. Na barra da esquerda, o ícone de Source Control mostra o que mudou.
  3. Escreva a mensagem do commit e clique em Commit & Push. Para uma branch nova, clique no nome da branch (canto inferior esquerdo) e crie a branch antes.
  4. Volte ao GitHub e abra o pull request.

O github.dev não roda o app. Para ver o resultado, baixe o fork (Code › Download ZIP) e abra src/index.html no navegador, ou aguarde o merge e veja em aprendendodev.com.br/app.

Em casa: Git e VS Code instalados (opcional)

  1. Instale o Git e o VS Code.
  2. No terminal: git clone https://github.com/seu-usuario/techburger.git
  3. Para cada tarefa: git switch -c nome-da-branch, edite, git add ., git commit -m "Verbo + o quê", git push -u origin nome-da-branch.
  4. Abra o pull request pelo site do GitHub.
