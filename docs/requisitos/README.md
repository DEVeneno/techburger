# Requisitos do TechBurger

Feitos na **Sprint 1 (Descoberta)**, a partir da entrevista com a cliente. Cada squad tem a sua pasta, e cada dev cuida de **um arquivo**: assim ninguém edita a mesma linha que o outro.

| Arquivo | O que tem | Formato |
|---------|-----------|---------|
| `entrevista.md` | Perguntas e respostas da entrevista com a Fernanda | Tabela pergunta / resposta |
| `regras.md` | Regras de negócio do módulo | Condição / ação / exceção (Aula 1) |
| `rf.md` | Requisitos funcionais | "O sistema deve..." + origem + MoSCoW (Aula 2) |
| `rnf.md` | Requisitos não funcionais | Categoria + qualidade com número (Aula 2) |

## Códigos dos IDs

| Squad | Código | Exemplos |
|-------|--------|----------|
| Cardápio | `CAD` | RN-CAD-01, RF-CAD-01, RNF-CAD-01 |
| Carrinho | `CAR` | RN-CAR-01, RF-CAR-01, RNF-CAR-01 |
| Pagamento | `PAG` | RN-PAG-01, RF-PAG-01, RNF-PAG-01 |
| Cozinha | `COZ` | RN-COZ-01, RF-COZ-01, RNF-COZ-01 |
| Cliente | `CLI` | RN-CLI-01, RF-CLI-01, RNF-CLI-01 |

Os IDs nunca mudam depois do merge: as histórias da Sprint 2 e os diagramas vão apontar para eles (rastreabilidade, Aula 9).
